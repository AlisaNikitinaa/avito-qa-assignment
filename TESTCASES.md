# Тест-кейсы API

Каждый сценарий использует собственные данные. Для защищённых запросов используется токен своего продавца, кроме API-07. Базовое объявление содержит уникальное название с кириллицей, ID продавца, цену 9900 и статистику `likes=21`, `viewCount=11`, `contacts=43`. Созданные объявления удаляются после теста.

| ID | Предусловие | Шаги | Ожидаемый результат |
|---|---|---|---|
| API-01 | Уникальные логин и пароль | Зарегистрировать и авторизовать пользователя. Создать объявление, прочитать его и статистику v1 и v2. Удалить и повторно получить запись и список продавца | Регистрация 201, положительный целочисленный ID и правильный логин. Авторизация 200 и непустой токен Bearer. Создание 200 и UUID. Чтение возвращает переданные поля и дату, обе версии статистики возвращают переданные счётчики. Удаление 200/204, чтение удалённой записи 404, список пуст |
| API-02 | Уникальные логин и пароль | Зарегистрировать пользователя дважды и авторизовать с исходными данными | 201, затем 409, авторизация успешна |
| API-03 | Полная пара логин/пароль | Удалить одно из полей и отправить запрос на регистрацию или авторизацию. Повторить для каждого поля и маршрута | 400 |
| API-04 | Известный и новый логины | Авторизоваться с неверным паролем известного пользователя и с новым логином | 401/403 |
| API-05 | Новый продавец | Прочитать список, создать два объявления одинаковыми запросами и снова прочитать список | Изначально список пуст. Созданы два разных UUID. В списке две записи с правильными данными |
| API-06 | Авторизованный продавец | Передать строку неверного формата и случайный корректный UUID в GET объявления, GET статистики v1 и v2 и DELETE | 400 для неверного формата, 404 для отсутствующей записи. [API-BUG-02](BUGS.md#api-bug-02) |
| API-07 | Сессия без входа | Вызвать все шесть защищённых ручек без Authorization, подставляя случайный UUID там, где нужен ID объявления | 401/403 |
| API-08 | Новый продавец | Создать и прочитать объявление с ценой 1 и отдельно с ценой 2 | 200 при создании и чтении, цена совпадает с переданной |
| API-09 | Собственное объявление со статистикой | Для каждой версии прочитать статистику, удалить объявление, проверить 404 при чтении карточки и повторно запросить статистику | До удаления 200 и исходные счётчики, после удаления ожидается 404 при отсутствии архива. [API-BUG-01](BUGS.md#api-bug-01) |
| API-10 | Новый продавец | По одному подставить 0 в каждый счётчик. Создать и прочитать объявление | 200, ноль сохранён. [API-BUG-03](BUGS.md#api-bug-03) |

Техники тест-дизайна — классы эквивалентности для учётных данных и UUID, граничные значения для счётчиков и малых положительных цен, переходы состояний при удалении, сравнение версий API. Дополнительно при чтении JSON проверяется Content-Type, при регистрации — отсутствие поля password в ответе.

Успешные коды регистрации, авторизации и создания взяты из коллекции Postman. Форматы чтения получены на стенде. Неописанные коды ошибок и поведение статистики после удаления рассматриваются как рабочие ожидания. Точные пределы полей в задании не заданы.
